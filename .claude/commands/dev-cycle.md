# /dev-cycle — 이슈 기반 개발 사이클 자동 진행

`$ARGUMENTS`로 받은 **이슈 번호** 기준으로 권장 작업 사이클(`docs/ai-workflow-guide.md` 6장)을 순서대로 진행한다.
완전 무인 자동이 아니라 **승인 게이트에서 멈추는 "자동 순서 진행"** 이다. 두 승인 게이트(플랜 / PR)는 절대 건너뛰지 않는다.

## 입력
- `$ARGUMENTS` = 이슈 번호 (예: `1`). "이슈 1번 개발 진행하자" 같은 자연어로 들어와도 **숫자만 추출**해 이슈 번호로 쓴다.
- 번호가 없으면 어떤 이슈인지 사용자에게 먼저 물어본다.

## 진행 순서

### 1단계: 이슈 확인 (이슈 생성 단계 건너뜀)
- 이슈는 **이미 존재**한다고 가정한다. `gh issue view <번호>` 로 제목·본문·라벨을 읽어 작업 범위를 파악한다.
- **새 이슈를 만들지 않는다.** (`/issue` 단계는 생략)

### 2단계: 조사 (researcher, 자동)
- `researcher` 에이전트로 이슈와 관련된 현재 코드/스펙 현황을 조사한다.
- 결과를 근거(`파일:라인`)와 함께 요약해 사용자에게 보고한다.

### 3단계: 계획 (planner 초안 → /grill-me 대화 → 확정)
- 먼저 `planner` 에이전트로 조사 결과 기반 **초안 플랜**을 만든다 (변경 파일 · 단계 · 리스크/영향 · 롤백 · 사람이 결정할 사항).
- 초안을 보여준 뒤, **사용자에게 `/grill-me` 입력을 요청하고 기다린다.**
  - ⚠️ `grill-me`는 `disable-model-invocation: true` 라서 **모델이 자동 실행할 수 없다.** 반드시 사용자가 직접 `/grill-me`를 입력해야 한다. "초안을 다듬으려면 `/grill-me`를 입력하세요"라고 안내하고 대기한다.
  - grill-me 세션에서 나온 결정사항으로 초안을 보완한다.
  - `/grill-me` 미설치거나 사용자가 건너뛰길 원하면: `AskUserQuestion`으로 핵심 결정사항·엣지케이스를 직접 캐물어 대체한다.
- 대화가 끝나면 **확정된 최종 플랜**을 정리해 보여준다.

### ⏸ 승인 게이트 1 — 플랜 승인
- 최종 플랜을 제시하고 **사용자 승인을 기다린다. 승인 전에는 코드를 수정하지 않는다.**

### 4단계: 브랜치 분기 + 구현 (승인 후에만)
- `develop` 최신 기준으로 `feature/<번호>` 브랜치를 만든다(이미 있으면 체크아웃). 팀 규칙: `feature/{이슈번호}`.
- 확정된 플랜대로 구현한다. **이때 변경에 대한 테스트 코드도 함께 작성한다**(프로덕션 + 테스트). 테스트 범위는 플랜에서 정한 대로 따른다.

### 5단계: 테스트 실행 (/test, 자동)
- `/test` 커맨드로 변경된 모듈의 테스트를 **실제로 실행**해 통과를 확인한다(추측 아님). 실패하면 고치고 다시 돌린다.

### 6단계: 셀프 검증 (reviewer, 자동)
- `reviewer` 에이전트로 `develop...HEAD` 변경을 점검한다(🔴 Must / 🟡 Should / 🔵 Nit). 🔴는 반영 후 재점검한다.

### 7단계: 커밋
- 포맷 확인(`./gradlew spotlessCheck` 등) 후, 팀 규칙 `[Type] #<번호> 요약` 형식으로 커밋한다.

### 8단계: PR 초안 (/pr)
- `/pr` 커맨드로 PR 초안(제목 · 본문 6섹션 · 리뷰어 · assignee)을 만든다. base는 `develop`, Draft. `✅ 테스트` 칸은 비워 두고, 5단계 `/test` 결과를 붙여 채운다.

### ⏸ 승인 게이트 2 — PR 업로드 승인
- 초안을 제시하고 **사용자 승인 후에만** Draft PR을 생성한다.

### 9단계: PR 리뷰 안내
- 생성된 PR 번호로 `/review-pr <PR번호>` 를 실행할 수 있음을 안내한다.

### 10단계: 리뷰 코멘트 대응 (/apply-review)
- PR에 리뷰 코멘트가 달리면(팀 리뷰는 보통 비동기로 나중에 도착) `/apply-review <PR번호>` 로 대응한다.
- 분류표 → ⏸ 사람이 건별 수용/거절 결정 → 수용 건은 **작업별 개별 커밋** 후 그 커밋 해시로 답글, 거절 건은 사유 답글.

## 원칙
- 두 승인 게이트(플랜 / PR)는 **절대 건너뛰지 않는다.**
- 각 단계로 넘어갈 때 무엇을 할지 한 줄로 알리고 진행한다.
- 팀 컨벤션은 `docs/backend-convention.md`(단일 출처)와 `CLAUDE.md`(아키텍처)를 따른다.
