## 작업 순서

**1단계: PR 정보 수집**

다음 명령어를 실행하여 PR 전체 내용을 파악하세요:
```
gh pr view $ARGUMENTS
gh pr diff $ARGUMENTS
```

**라인 번호 검증 필수**: `gh pr diff` 출력의 라인 번호는 diff 파일 자체의 라인이지 변경된 소스 파일 라인이 아닙니다.
코멘트 제안에 사용할 라인 번호는 반드시 **PR 브랜치의 실제 파일** 기준이어야 하므로 아래 순서로 검증하세요.

1. `gh pr view $ARGUMENTS --json headRefName,headRefOid -q '.'` 로 PR 브랜치명과 commit SHA 확인
2. `git fetch origin <headRefName>` (로컬에 없으면)
3. 코멘트 달 파일마다 `git show origin/<headRefName>:<파일경로> | cat -n` 로 PR 브랜치 기준 라인 번호 확인
4. 이 라인 번호를 코멘트 제안의 `위치:` 필드에 기재

**2단계: 시니어 관점 분석**

단순 스타일 지적이 아닌, 다음 기준으로 심층 분석하세요:

- **설계/아키텍처**: DDD 계층 위반, 책임 분리 문제, 의존 방향 이상
- **트랜잭션 안전성**: `@Transactional` 누락/위치 오류, 트랜잭션 경계 밖에서 DB 접근
- **동시성/성능**: N+1 쿼리, 불필요한 전체 조회, 인덱스 미고려
- **예외 처리**: 예외 삼킴, `BusinessException` 미사용, 잘못된 HTTP 상태 코드
- **보안**: 인가 없는 리소스 접근, 민감 데이터 노출, SQL Injection 가능성
- **팀 컨벤션 위반** (단일 출처: `docs/backend-convention.md`):
  - `@Transactional`은 Facade가 아닌 UseCase에만
  - `ApiResponse.onSuccess(...)` 응답 통일
  - `ErrorStatus` 형식: `모듈_상태코드_세자리번호`
  - URL prefix: `/api/{version}/{module}/` (모듈명 단수)
  - 코드 줄 길이 100자 초과 (Checkstyle `LineLength max=100`)
  - Swagger 어노테이션 별도 파일 분리
  - UseCase 파일명: `{Module}{Function}UseCase`
  - 커밋 메시지 형식: `[라벨] #이슈번호 {내용}`
- **테스트 가능성**: 테스트하기 어려운 구조인지
- **가독성**: 메서드 길이, 네이밍 명확성, 불필요한 복잡도

**3단계: 코멘트 제안 목록 출력**

### 코멘트 제안 목록

각 항목은 다음 형식으로 작성:

```
[번호] [심각도: 🔴 Must / 🟡 Should / 🔵 Nit]
파일: {파일경로}
위치: {라인번호 또는 라인범위, 예: L42 / L30-L45}
코멘트 내용:
{GitHub PR 코멘트에 그대로 붙여넣을 수 있는 한국어 코멘트.
 왜 문제인지, 어떤 방향으로 개선이 필요한지 설명한다.
 절대로 개선된 코드 예시(java 코드 블록 등)를 제시하지 않는다.
 작성자 스스로 해결 방법을 찾도록 질문형 또는 방향 제시형으로 작성한다.}
```

심각도 기준:
- 🔴 Must: 버그, 보안 취약점, 트랜잭션 오류 등 반드시 수정 필요
- 🟡 Should: 설계 문제, 성능 이슈, 팀 컨벤션 위반 등 수정 권장
- 🔵 Nit: 가독성, 네이밍, 사소한 스타일 등 선택적

### Finish your review 코멘트 제안

GitHub PR 리뷰 제출 시 전체 요약으로 사용할 수 있는 코멘트를 아래 형식으로 작성하세요.

- **길이는 2-3줄로 짧게 유지한다** (문단/줄바꿈 포함 최대 3줄). 길게 늘어뜨리지 말 것.
- 전체적인 구현 흐름과 완성도를 자연스럽게 인정하는 문장으로 시작한다.
- 🔴 Must 항목은 "확인 부탁드립니다" 등 부드럽게 요청하는 톤으로 언급한다.
- 🟡 Should / 🔵 Nit 항목 중 핵심적인 것만 간략히 언급하거나 생략한다 (Nit은 보통 생략).
- 명령·지시형이 아닌 동료에게 말하듯 친근하고 가볍게 작성한다.
- 마지막은 이모지(:), 수고하셨습니다 등으로 마무리해도 좋다.
- 코드 예시는 포함하지 않는다.
