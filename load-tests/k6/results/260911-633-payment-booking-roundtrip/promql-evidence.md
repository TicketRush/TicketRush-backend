# PromQL 증적 — #633 회차 1

이 회차에는 `timeseries-*.json` 과 Grafana 캡처가 **없다**. SSH 키가 없어 터널(`-L 9090`)을
띄우지 못했고, 그래서 k6 의 remote-write 도 쓰지 못했다. 대신 EC2 셸에서
`localhost:9090` 에 직접 질의해 값을 떴고, **그 질의문과 출력을 여기에 남겨 재현 경로를 보존한다.**

수치의 SSOT 는 `metadata.txt` 다. 이 파일은 그 수치가 어떤 질의에서 나왔는지를 보인다.

---

## 1. 왜 `@ modifier` 로 구간을 고정해야 하는가

히스토그램 버킷은 **누적 카운터**다. 그래서 `increase(...[3m])` 같은 상대 창은 **조회 시점**을
기준으로 뒤를 돌아본다 — 회차가 끝나고 몇 분만 지나도 창이 run 바깥을 덮어 `NaN` 이나 0 이 나온다.

`@ <epoch>` 로 평가 시점을 run 종료 시각에 고정하면, 조회가 얼마나 늦어지든 **그 run 의 구간을
정확히 복원**할 수 있다. 이 회차의 버킷 수치는 전부 이 방식으로 떴다.

| run | 구간(UTC) | 창 | `@ epoch` |
|---|---|---|---|
| W1 | 11:55:26 ~ 11:58:26 | `[3m]` | `1789127906` |
| B  | 12:40:24 ~ 12:50:44 | `[11m]` | `1789131044` |
| B1 | 12:40:24 ~ 12:45:24 | `[5m]` | `1789130724` |
| B2 | 12:45:44 ~ 12:50:44 | `[5m]` | `1789131044` |
| W2 | 12:58:37 ~ 13:01:37 | `[3m]` | `1789131697` |

> ⚠ Micrometer 의 `_max` 는 이 방식으로 복원할 수 **없다.** 롤링 2분 창이라 run 종료 직후에
> 뜨지 않으면 값 자체가 사라진다. W2 에서 실제로 놓쳐 `542.27ms` 는 과소값이다.

## 2. 질의문

라벨: `{outcome="success", instance="payment-service:8090"}` · job 은 `ticketrush-services`.

```promql
# 분위수 (p 는 0.50 / 0.95 / 0.99)
histogram_quantile(0.99,
  sum by (le) (increase(
    ticketrush_payment_booking_lookup_seconds_bucket{outcome="success",instance="payment-service:8090"}[3m]
    @ 1789127906)))

# 버킷 누적 (le 별)
sum by (le) (increase(
  ticketrush_payment_booking_lookup_seconds_bucket{outcome="success",instance="payment-service:8090"}[3m]
  @ 1789127906))

# outcome 별 호출량
sum by (outcome) (increase(
  ticketrush_payment_booking_lookup_seconds_count{instance="payment-service:8090"}[3m]
  @ 1789127906))

# booking 서버 자체 처리(왕복의 하한 축)
histogram_quantile(0.99,
  sum by (le) (increase(
    http_server_requests_seconds_bucket{instance="booking-service:8090",uri=~".*internal/booking.*"}[3m]
    @ 1789127906)))
```

B1/B2 분리 조회는 `b1b2-split-query.sh` 로 묶어 두었다(같은 질의에 `[5m]` 과 위 표의 epoch 을 넣는다).

> 🔴 **EC2 웹 터미널은 붙여넣기에서 따옴표를 유실한다.** PromQL 은 라벨 매처에 따옴표가
> 필수라 그대로 붙여넣으면 조용히 다른 질의가 된다. 이 회차는 스크립트를 base64 한 줄로
> 감싸 전송하는 방식으로 우회했다(`echo <base64> | base64 -d > /tmp/q.sh && bash /tmp/q.sh`).

## 3. 버킷 누적 분포 (outcome=success)

`increase(..._bucket[창] @ epoch)` 의 출력을 누적 비율로 환산한 것이다.

| le | W1 누적 | B 누적 | W2 누적 | W1 구간건수 | W2 구간건수 |
|---|---|---|---|---|---|
| 1ms | 0.00% | 0.00% | 0.00% | 0 | 0 |
| 2ms | 0.00% | 0.16% | 0.00% | 0 | 0 |
| 5ms | 17.43% | **92.61%** | 16.77% | 244.4 | 241.3 |
| 10ms | 80.00% | 99.36% | 80.88% | 877.2 | 922.5 |
| 25ms | 98.55% | **100.00%** | 98.87% | 260.0 | 259.0 |
| 50ms | 99.50% | 100% | 99.51% | 13.3 | 9.2 |
| 100ms | 99.50% | 100% | 99.51% | **0** | **0** |
| 250ms | 99.64% | 100% | 99.65% | 2.0 | 2.0 |
| 500ms | 99.79% | 100% | 99.79% | 2.0 | 2.0 |
| 1s | 100% | 100% | 100% | 3.0 | 3.0 |
| 2s | 100% | 100% | 100% | 0 | 0 |

총 건수(increase 외삽): **W1 1401.93 · B 6275.63 · W2 1438.99**

초과 건수:

| 기준 | W1 | B | W2 |
|---|---|---|---|
| >25ms | 20.3건 (1.45%) | **0건** | 16.2건 (1.13%) |
| >50ms | 7.0건 (0.50%) | 0건 | 7.0건 (0.49%) |
| >100ms | 7.0건 (0.50%) | 0건 | 7.0건 (0.49%) |
| >250ms | 5건 | 0건 | 5건 |
| >500ms | 3건 | 0건 | 3건 |
| >1s | 0건 | 0건 | 0건 |

**읽는 법 두 가지**

1. **50~100ms 는 세 run 모두 0건인 빈 구간이다.** 임계를 50ms 로 잡든 100ms 로 잡든 초과
   건수가 같다 — 즉 100ms 는 검출력을 하나도 잃지 않으면서 여유만 두 배다.
   `slowCallDurationThreshold = 100ms` 권고의 핵심 근거가 이 빈 구간이다.
2. **W1 과 W2 의 꼬리가 건수 단위로 일치한다**(7/7 · 5/5 · 3/3 · 0/0). 워밍업 꼬리가 우연이
   아니라 재현되는 현상이라는 뜻이고, 그래서 임계를 이 꼬리 위에 세울 수 있다.

> ⚠ 값이 소수인 것은 `increase()` 가 스크랩 경계에서 외삽하기 때문이다. 호출량의 SSOT 는
> k6 iteration 수이고(W1 1440 · B 6200 · W2 1441), Timer 건수는 `lookup:booking` 1:1 대조용이다.

## 4. outcome 별 분포

| outcome | W1 | B | W2 |
|---|---|---|---|
| `success` | 1401.93 | 6275.63 | 1438.99 |
| `failed` | 18 | 0 | 0 |
| `not_found` | 0 | 0 | 0 |

`failed` 18건은 W1 에만 나왔고 최대 1171ms 로 **read-timeout(1s)에 도달**했다.
`not_found` 가 0인 것은 코호트가 전부 실재하는 예매이기 때문이다 — 이 갈래는 #571 에서
서킷 실패로 세지 않을 분류라 회차가 일부러 비워 둔 축이다.

> ⚠ **소유자 불일치는 `not_found` 가 아니라 `success` 로 기록된다.** #572 의 소유자 대조는
> `getBooking` 이 200 을 반환한 *뒤* UseCase 가 하는 판정이라, Timer 관점에서는 정상 왕복이다.
> 시딩이 오염되면 분포에 조용히 섞이는 경로이므로 게이트 `owner_ok=10000` 이 그것을 막는다.
