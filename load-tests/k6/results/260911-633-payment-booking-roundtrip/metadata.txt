# ── 🔴 한계 2: Rate Limit 을 완화한 상태의 측정이다 ─────────────────────────
LIMIT_RATE_LIMIT=같은 배포(PR #635, #423)에 게이트웨이 Rate Limit 이 들어왔다.
#   운영 기본값에서는 이 회차의 호출량 자체가 불가능하다:
#     payment-confirm-rate-limit : replenishRate 3 · burstCapacity 120 · requestedTokens 60
#       -> 사용자당 허용 = 3/60 = 0.05 req/s = 분당 3건 (버스트 2건)
#     booking-create-rate-limit  : replenishRate 5 · burst 120 · tokens 60 -> 사용자당 분당 5건
#   (gateway-service/src/main/resources/application.yml:64,66)
#   키는 userOrIpKeyResolver (X-User-Id 있으면 user:{id}, 없으면 ip:{addr}).
#   ⚠ 이 리밋은 **사용자당**이고 서킷브레이커 윈도우는 **인스턴스 전역** 집계다.
#     따라서 "운영 confirm 상한 = 분당 3건"은 성립하지 않는다 — 전역 도달량은
#     동시 confirm 사용자 수 × 분당 3건이다. report.md §10.1 에서 다룬다.
#   회차 동안만 아래로 완화하고 종료 후 원복했다(.env 백업 .env.bak.20260911-115409):
#     RATE_LIMIT_PAYMENT_CONFIRM_REPLENISH_RATE=900  BURST=1800  (= 15 req/s)
#     RATE_LIMIT_BOOKING_REPLENISH_RATE=1500         BURST=3000  (= 25 req/s)
#   gateway 만 --force-recreate --no-deps 로 재생성(restart 는 env_file 을 다시 읽지 않는다).
#   스크립트: rate-limit-relax/20-rl-relax.sh · 21-rl-restore.sh
